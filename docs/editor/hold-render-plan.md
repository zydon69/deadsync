## Source contracts

Reference GrooveAuthor `48e18f71655d0f0d86144c63239331833501fda2` (MIT).

- `EditorHoldNoteEvent.cs:493–494`: active body lighting requires both active
  hold and LightHolds; cutoff requires active hold and HideArrows independently.
- `HoldRenderState` at lines 283–303: start fill gets raw `startActive`, while
  body/end fills get the LightHolds-filtered active state. Rim textures use
  selection but are not tinted by the hold fill color.
- `EditorHoldNoteEvent.cs:511–580`: source head center, cap position, optional
  centered caps, solo start segment and reverse reflection. Cutoff moves the
  head/body start without moving the tail or resetting its tile phase.
- `DrawBody` at lines 380–458: bottom-to-top body tiles, partial top tile samples
  the bottom of its source rectangle. Offscreen distance is skipped before
  iteration; the native helper additionally exposes an output budget and partial
  state rather than silently allocating an arbitrary number of actors.
- `ArrowGraphicManager.cs:557–600`: Dance holds use separate fill/rim body/cap;
  Roll uses its own fill with the same selected/unselected hold rim.
- Lines 755–815: Solo always uses the narrow solo body/cap, even on cardinal
  arrows. Only its diagonal heads have the extra start graphic.
- Lines 937–979: SMX uses center hold body/cap even for cardinal arrow heads.
- Lines 1253–1261 and 1304–1350: PIU caps are centered arrow graphics, have the
  lane's rotation, and do not flip in reverse. Right-hand bodies mirror
  horizontally. PIU cap color is note color, not held body color.
- `PreferencesNoteColor.cs:523–549`: XNA fill variant multipliers are 1.5 for
  held, 1.7 for selected, multiplied in that order before clamping/byte packing.
  UI/minimap multipliers 1.5/8.0 and packed-color multiplication differ and are
  owned by the separate minimap implementation.
- Lines 639–652: multiplayer fill palette blends base hold/roll with the player
  palette using default RoutineNoteColorAlpha 0.90 before computing variants.

## Prepared modules and evidence

- `hold_geometry.rs`: source top-edge geometry, reversed/normal body tiles,
  source crops, optional start/cap, and explicit partial result.
- `hold_colors.rs`: exact XNA channel arithmetic and source default Dance
  hold/roll/player colors, raw-active versus LightHolds and HideArrows policy.
  `piu_fill.rs` supplies the separate exact HSV conversion. Shared custom
  preferences are being coordinated through the core note-color DTO.
- `hold_graphics.rs`: selected/unselected atlas ID resolution by source layout,
  lane and hold/roll kind; no invented active texture names.
- `hold_atlas.rs`: 56 original non-mip fill/rim rectangles, verified within the
  1280px PNG. Existing `editor-grooveauthor/PROVENANCE.json` records the correct
  PNG/root-atlas pair and MIT license. Content/atlas.json is a different packing.
- `scripts/editor-hold-geometry-oracle.py`: 18 .NET cases execute unchanged Draw,
  DrawBody, DrawStart, DrawEnd and reflection/flip methods. Constructor supplies
  explicit texture dimensions; a graphics adapter records calls. This verifies
  geometry, not original texture resolution, GPU output or timing.
- `scripts/editor-hold-colors-oracle.py`: 20 .NET cases execute unchanged
  ArrowColor plus original MonoGame float/int Color constructors from pinned
  submodule `8e61b2effa9f8775bd63f24dc33b2f7924f9eba2`.
  The Color.cs file is downloaded from that immutable GitHub raw URL and its
  bytes are checked against a fixed SHA256. The original GrooveAuthor source is
  separately compared byte-for-byte against git show. UI helpers are inert
  adapters because only XNA fill fields are observed; full preference/cache or
  layout palette resolution is not claimed.

Validated native targets: `edition_hold_geometry` (6), `edition_hold_colors` (3),
`edition_hold_graphics` (3), `edition_hold_palette` (3), `edition_hold_render` (3),
and `edition_piu_fill` (2): **20 passed** in central execution. These use path
modules without declaring production imports. A third original .NET oracle
executes 24 PIU HSV/BlendColor/Desaturate cases against byte-verified source.

The first geometry oracle run exposed a recording-adapter defect: cap-fill and
start-fill dimensions incorrectly fell back to body height. The adapter now
resolves the same dimensions for fill and rim; fixtures were regenerated by
executing the unchanged original methods. The Rust comparisons remained intact.

`hold_render.rs` now emits real original-atlas Sprite actors in body/start/cap/head
order, including cropped tiles, selected rims, independent fill colors, reverse
UVs and PIU unflipped arrow caps. `hold_palette.rs` resolves source default
Dance/SMX and lane/row-based PIU colors. No runtime calls are connected yet.

## Next integration boundary

A temporary unapplied patch shares the renderer between focused/inactive note
passes, preserves each view's selection and participant, and uses the existing
active/cutoff policy. Its body-strip budget is divided with the existing note
budget and accumulated across ranges; partial results use the existing visible
notice. Only note query ranges receive sprite padding so a cap extending beyond
its end row is still considered; other overlays retain their original ranges.

Source `ActiveEditorChart.cs:1193–1199` extends the hold's H by the cap extent
before Draw: tail Y plus capHeight×scale×scrollSign, using half that extent for
centered PIU caps (`GetHoldCapHeight`, line 855). The bridge preserves this; a
simple tailY−headTop would place the cap too early.

Prepared `edition_hold_runtime_workflow` has three State paths for Dance/Couple,
Routine owners/selection, Solo reverse and PIU. It must run only after applying
the shared bridge. Shared NoteColor/Options preferences will be injected through
media's single core DTO; no second color storage is introduced.
