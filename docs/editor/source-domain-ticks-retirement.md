## Retirement ownership and bound

Production creates one ready producer/control thread and one callback consumer in deadlib-audio/src/launch.rs::output_transport. Before output starts, the receiver transfers its unique return producer into RenderState. The ready capacity C is the actual requested capacity (production128); return capacity N=C+MAX_ACTIVE_SFX32+one pending holder, hence161 in production. Every accepted scheduled message consumes exactly one private transport credit. Credits are restored only when the control thread reclaims returned snapshots. Thus at most N credited messages can exist across ready queue, active voices, callback pending and returned queue; a schedule being returned implies at most N-1 other returned messages. Return cannot overflow under production ownership. Defensive failure retains an inactive schedule/pending message and stops draining, never frees its window in the callback.

All replacement, stale discard, cancellation and renderer pruning return schedule ownership before removing the active holder. No callback allocation, lock, wait, producer reclamation or final window destruction occurs. Source lookup is bounded binary search over the validated window, then at most one onset consumption per output frame. One window is producer-validated to at most2,000,001 source entries. The credit bound limits outstanding window count; it does not make the existing maximum-size window cheap.

SfxCache reclaims returned snapshots on UI asset polling and before subsequent enqueue. Without UI activity, retention remains bounded until session teardown. A full ready queue rejects owned messages on the producer; it cannot accumulate events while no callbacks run. Ready and return rtrb storage survives whichever endpoint closes first. AudioEngine declares live output before cache; StreamManager shuts down/joins backend callbacks before cache teardown. RenderState destructor may perform final destruction only after callback shutdown, never from render(). An abandoned ready consumer rejects further publications. The actual RT path drains SfxReceiver::try_iter; arbitrary caller-provided owning iterators remain outside this ownership contract.
