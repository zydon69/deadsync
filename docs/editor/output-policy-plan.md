# Format-changing Save As: output policy separate from edit history

Status: architecture proposal, not implemented or runtime tested. Existing
same-format native Save As and detached `advanced_export::Output` stay separate.

## Required ownership

`Document.format` describes the immutable backing text and pending native edit
encoding. `FileSession` should separately own an output policy describing the
persisted target format and six save options. This is session storage state,
not a `DocumentSwap` undo entry. Otherwise Undo can restore an SM Document while
the current path ends in `.ssc`, and the next ordinary Save writes wrong bytes.

A policy must use a chart GUID for the shared timing source, never a bare chart
index which can refer to a different chart after reorder/deletion. Before each
write resolve that GUID against current chart IDs. If it no longer exists,
request a new explicit choice. Defaults can select the currently focused chart
when preparing a new review. Chartless Untitled requires an explicit supported
branch: the existing advanced writer requires a timing chart.

Keep a lossless native-serialization policy distinct from advanced output.
Turning every existing Save into the current advanced writer would reject or
rewrite unknown properties which existing native Save deliberately preserves.
A format-changing Save As chooses advanced output explicitly; ordinary native
Save on an unconverted file keeps its existing exact preservation contract.

## Publication sequence

1. Prepare a detached relocation over live and historical media paths with the
   existing same-format history rebasing algorithm. Keep the live Document and
   its codec unchanged; media paths must be rebased before the detached export.
2. Build a fresh advanced preflight over that detached current content, target
   policy and resolved timing GUID. The review owns exact content/GUID tokens.
   New edits and policy changes invalidate it. Undo/redo invalidates it while
   content differs; returning to the exact approved content without a new edit
   may reuse its review. A new edit followed by Undo remains invalid because the
   monotone next-revision lifetime changed. Existing loss approval
   is not an unlimited approval for later newly introduced losses.
3. Generate target bytes and validate their semantics. A writer output is not a
   durable publication receipt. It must expose or transfer its token ownership
   without allowing callers to invent output bytes or substitute another policy.
4. Publish through the existing reviewed-target and durable replacement path.
   The baseline/`expected` bytes are the actual generated bytes, not the native
   Session serialization. Preallocate all target path/policy/history/view
   updates before publication. A late durability error retains the existing
   pending receipt model; never report that the file was not written.
5. Install target path, policy and relocated native history only after the
   successful publication boundary. Keep source codec unchanged. Mark the exact
   approved content clean; edits after publication remain dirty.
6. Subsequent Save uses the persisted policy and a new preflight. If Undo adds
   an unrepresentable chart/event/property, refuse Save without changing source
   or history. Recovering an earlier native document never silently resets the
   persisted target format.

An export COPY command is simpler: target bytes publish independently, while
path, policy, current native history and dirty state remain unchanged. This is
not a substitute for implementing original Save As.

## Recovery is lossless

Automatic recovery must **not** run the lossy export policy. Store native
`Session.serialize()` content with its source codec and an envelope containing
output policy, timing GUID, target identity and current expected-byte ownership.
Anonymization, custom-data omission and SM downgrades must never erase data from
crash recovery or require an interactive loss review in a background worker.
Existing recovery magic/version must migrate intentionally; distinguish legacy
recovery by its format rather than guessing from the target path extension.
Restore native content and output policy independently, retaining external
change checks against the real target bytes.

## Minimum future validation

- SM→SSC and SSC→SM, then undo a structural DocumentSwap and Save again: extension
  and output codec agree while native history remains usable.
- Both dirty and clean histories, redo branches, profile side effects and chart
  focus/position survive relocation without replaying independent effects.
- A saved lossy policy plus Undo that introduces a new warning/error cannot
  reuse an earlier approval. Reorder resolves the same timing GUID; deletion
  requires a new explicit timing choice.
- Recovery after anonymized/omitted output restores all unsaved native metadata
  and retains target format/options. Legacy recovery remains readable.
- Review stale after edit→Undo, changed destination, write failure, late sync
  failure and retry, new edits before retry, source-preserving export copy.
- No-chart Untitled, invalid peer charts and arbitrary unknown vendor fields
  retain the native Save contract or are explicitly refused before publication.


## Isolated model prepared

The model is declared in the primary tree. The parent coordinator validated its
five workflow tests. `patches/editor-output-policy-model.patch` records the
original module addition; do not reapply it. The shared monotone guard rejects
edit→Undo review reuse.

The model has NativeLossless and Advanced variants, resolves the timing GUID
against current chart identities on each preparation, and returns detached
prepared/output values. Only exact warning indices authorize advanced generation.
Output bytes and policy are privately owned and currentness remains inspectable;
no storage path, clean flag, history, publish, recovery or Preferences mutation
is performed. NativeLossless supports chartless documents and preserves raw
unknown vendor fields without routing through the advanced serializer. Its byte
limit after Session serialization does not claim a peak allocation cap.

Five validated model workflow tests cover unknown/chartless native output; target codec
independent of native source Undo and rejected reintroduced Warps; timing GUID
under presentation reorder/source deletion shift/missing chart; new warning
requiring new review and monotone edit→Undo invalidation; limits/cancel/foreign
session without mutation. The presentation-order check is deliberately separate
from structural source mutation: the current chart list sorts presentation only.


## Storage integration draft — 28 October 2026

`patches/editor-output-storage-draft.patch` is an isolated, unapplied storage
lot (13 files). Its base and working copy retain the publication witness: a
relocation receipt, including its output-policy transition, activates only after
the real in-memory publication commits. No Cargo run has validated this lot. The parent has separately validated all
70 core tests after the publication witness fix.

The draft keeps the native source codec/history separate from persisted output
policy. Save/SaveAs prepare a fresh typed review; SaveAs reviews the candidate
after media rebasing. Policy revision allocation precedes namespace publication;
a late directory-sync failure installs the published policy and retains an exact
retry receipt. NativeLossless on a mismatched target extension requires SaveAs.

Recovery V2 stores lossless native bytes, explicit source codec, target identity,
policy and validated unique chart GUIDs; V1 remains readable. Recovery invokes
no lossy serializer or interactive warning review. A monotone publication epoch
invalidates old recovery snapshots even after byte-identical saves under the same policy,
SaveAs leaving the old source intact, or Recovery installation.

Twenty-two unexecuted storage tests are prepared: six public workflows and sixteen
private cases for pending durability, pre-publication failure, policy overflow,
stale recovery, malformed envelopes, GUID validity and non-Unicode target paths.
`patches/editor-output-storage-workflows.rs` preserves the public test source
outside automatic test discovery until this lot is installed. Advanced chartless
conversion is explicitly unsupported; NativeLossless chartless Save remains
supported. Native advanced-export UI must wait for storage validation.

The autorecovery scheduler also compares policy and publication revisions when deduplicating
completed receipts, so identical native revision/baseline bytes cannot suppress
a new snapshot carrying a changed policy.

Recovery V2 now declares exact `content_length`, bounded at 256 MiB; decoder
rejects shorter or longer native payloads even when the remaining prefix/extra
tags are independently parseable. V1 retains its explicit legacy decoder. Two
additional unexecuted tests cover exact framing and V1 compatibility.
